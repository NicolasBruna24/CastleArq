# B9.46 — GGUF Inspection Capability Decision

## 1. Problem

B9.46.15 quedó bloqueado porque CastleArq no tenía una capacidad existente para leer `general.architecture` desde un artifact GGUF físico. La metadata real observada es `qwen2`, pero el flujo actual no la conserva ni la transporta al strict evaluator.

Este bloque decide únicamente el mecanismo técnico de lectura. No implementa parser, representación, evaluación ni persistencia.

## 2. Existing capabilities

Auditoría read-only del repositorio, packaging y entorno:

* `pyproject.toml` declara `setuptools` y no tiene dependencias runtime.
* No hay `requirements.txt`, `uv.lock`, `poetry.lock` ni otra dependencia GGUF declarada.
* `app/` no contiene parser/utilidad GGUF.
* `llama` está instalado como `/home/brunapc/.local/bin/llama`, versión `0.4.0-dev (build 10909, commit a2878d30d)`.
* `llama --help`/`llama cli --help` expone carga, inferencia, `--version`, `--model` y opciones de runtime, pero no una interfaz documentada para consultar metadata GGUF.
* `llama-server` y `llama-cli` no están instalados como comandos separados.
* `strings` puede encontrar claves y valores en el header, pero no es una API GGUF estable ni una forma fiable de parsear tipos, longitudes, endianness o metadata ausente.
* `huggingface.py` descubre metadata remota de archivos, pero explícitamente no solicita contenido GGUF y no puede aportar `general.architecture` de un artifact local.
* Los tests actuales no contienen fixture ni parser GGUF productivo.

## 3. Candidates

### Opción A — Capacidad existente de llama.cpp

**Rechazada.** `llama` puede cargar y ejecutar el artifact, pero no expone de forma documentada `general.architecture` como salida estructurada ni como contrato de aplicación. La salida humana de carga no es una API estable y no distingue formalmente metadata ausente, valor desconocido o error de archivo.

### Opción B — Dependencia especializada GGUF

**Rechazada por falta de disponibilidad.** No existe una dependencia Python GGUF en el entorno o declarada por el proyecto. Investigar paquetes externos introduciría una decisión de dependencia, licencia, versionado y distribución todavía no resuelta.

### Opción C — Parser GGUF mínimo propio

**Seleccionada conceptualmente.** Un lector bounded puede validar el header, recorrer la metadata necesaria, leer exactamente `general.architecture` y devolver:

```text
architecture_raw
architecture_provenance = GGUF general.architecture
```

No debe leer tensores ni其它 metadata, convertir `qwen2` en otra architecture, producir estado/identidad/conclusiones ni añadir dependencias externas.

Los riesgos —endianness, tipos, versiones, truncamiento, metadata ausente— exigen fixtures y errores explícitos antes del uso productivo. No se implementa aquí.

### Opción D — Otra capacidad existente

No aplica. `ArtifactFilesystemInspector` sólo lee estado y `evaluation_adapter` es puro.


## 4. Evaluation

El parser seleccionado no altera la inferencia, no requiere sudo/root, no instala drivers y no cambia el contrato CPU-first. Es portable con Python siempre que soporte explícitamente las versiones GGUF declaradas y pruebe sus fixtures.

```text
GGUF header
  -> key general.architecture
  -> architecture_raw
  -> provenance GGUF general.architecture
```

## 5. Selected mechanism

```text
GGUF-INSPECTION-CAPABILITY-DECISION = C
SOURCE = minimal in-process GGUF header reader
OWNER = physical artifact inspection boundary
DEPENDENCY = none beyond Python standard library and the GGUF format contract
INPUT = physical GGUF artifact path/file handle
OUTPUT = architecture_raw + fixed provenance `GGUF general.architecture`
PERSISTENCE = NONE
PROVENANCE = GGUF metadata key general.architecture
SCOPE = header validation and exact key lookup only
IMPLEMENTATION-BLOCK = bounded parser and fixture tests; do not integrate it yet
```

## 6. Rejected mechanisms

* `llama` CLI: no ofrece API de metadata contractual.
* `llama` human output: frágil, coupled a versión y no estructurado.
* `strings`: incidental, no parsea encoding/longitudes ni ausencia.
* Dependencia Python externa: no disponible/declarada y añade una decisión de distribución.
* ModelStore como parser: mezcla ownership de filesystem/state con metadata semántica.
* evaluation_adapter como reader: violaría el boundary puro.
* Reutilizar ModelSpec.architecture: no representa evidencia física.

## 7. Ownership

El owner conceptual es una capacidad de inspección física read-only. El producer será la futura lectura GGUF; el consumer será la evaluación mediante evidencia ya derivada. Lifecycle:

```text
read header
  -> derive evidence
  -> consume during evaluation
  -> discard
```

No se persiste en manifest, ArtifactSpec, ModelStore state ni filesystem cache.

## 8. Dependency contract

El mecanismo no requiere dependencia Python ni herramienta del sistema. La distribución conserva runtime llama.cpp externo, CPU-first, no-sudo/root y no instalación automática. La compatibilidad GGUF debe estar acotada por versión y probada.

## 9. Error semantics

```text
GGUF válido + general.architecture presente
  -> evidence with raw value

GGUF válido + general.architecture ausente
  -> metadata_missing / unknown evidence, not parser failure

archivo inválido, magic/version inválido o header truncado
  -> invalid artifact/read error

valor presente pero no reconocido por Knowledge
  -> evidence exists; strict check remains UNKNOWN
```

`unknown architecture` no significa `parser failure`; el parser no convierte ausencia en UNSUPPORTED.

## 10. Implementation boundary

B9.46.17 podrá implementar exclusivamente un parser GGUF mínimo in-process, lectura read-only de `general.architecture`, provenance exacta, errores diferenciados y fixtures binarios pequeños para válido, metadata ausente e inválido.

B9.46.17 no debe integrar todavía la evidencia en ModelSpec, ArtifactSpec o ModelArtifact, ni modificar Knowledge, evaluator, admission, persistencia, ModelStore, resolver, preflight, execution, o crear un segundo pipeline. No debe hardcodear `qwen2` ni normalizar `qwen2 -> qwen3`.

## 12. Implementation record — B9.46.17

La capacidad fue implementada en:

```text
app/gguf_reader.py
```

Representación:

```text
GGUFArchitectureEvidence
  architecture_raw: str | None
  architecture_provenance = "GGUF general.architecture"
  present: bool (derived)
```

El lector:

* acepta GGUF versions 2 y 3;
* valida magic, versión, conteos y límites de lectura;
* recorre metadata KV por nombre exacto;
* salta tipos escalares, strings y arrays soportados;
* falla explícitamente ante magic inválido, versión no soportada, truncamiento, longitudes inseguras y tipo metadata no soportado;
* devuelve `architecture_raw=None` cuando la key no existe;
* no convierte el valor, no normaliza y no hardcodea `qwen2`.

Los fixtures binarios mínimos se generan de forma autocontenida en `tests/test_gguf_reader.py` para evitar añadir un binario al repositorio. Cubren:

* `general.architecture=qwen2`;
* metadata válida sin `general.architecture`;
* key parecida que no debe coincidir;
* metadata target después de otra key;
* magic inválido;
* truncamiento;
* tipo metadata no soportado.
