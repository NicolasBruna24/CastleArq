## 3. Current State Audit

### Packaging

`pyproject.toml` contiene `setuptools.build_meta` con `setuptools>=61`, `project.name = "castlearq"`, `version = "0.1.0"`, `requires-python = ">=3.10"`, metadata y `pythonpath = ["."]` para pytest. No contiene `dependencies`, `[project.scripts]`, `setup.py`, `setup.cfg` ni `MANIFEST.in`. El discovery no está declarado explícitamente y debe verificarse contra `app/`; `pythonpath` no es una estrategia de instalación. `pyproject.toml` es la fuente de verdad de versión, aunque la API actual lo lee directamente.

### CLI

`app/main.py` contiene `main() -> int`, `argparse` y `prog="castlearq"`. No usa subparsers: recibe `command`, `provider`, `repository` y flags. Comandos: `detect`, `diagnose`, `verify`, `models`, `list`, `source`, `plan`, `download`, `run`, `execute`, `chat`, `serve`. `--help` existe; `--version` no existe. `if __name__ == "__main__"` ejecuta `raise SystemExit(main())`, por lo que `python3 -m app.main` es la interfaz existente. `argparse` produce 2 para uso inválido y los handlers usan principalmente 0/1.

Los imports son relativos dentro de `app`, pero no existe metadata de distribución para validar el paquete fuera del checkout. Ningún módulo debe requerir el cwd.

### Configuration

`app/compatibility.py` contiene `load_config(path: Path = Path("config/config.toml"))`; `app.main` la llama sin argumento en `print_models()`. El parser es manual, devuelve defaults si el archivo no existe y lanza `ValueError` para valores inválidos. La ruta por defecto es relativa al cwd y el archivo del repositorio no está packaged como configuración de usuario. No existe `app/config.py` ni bootstrap separado.

### ModelStore

`app/model_store.py` contiene `ModelStore`, `default_models_directory()` y las rutas `~/.local/share/castlearq/models` y `~/.local/share/localai-hub/models`; no usa `XDG_DATA_HOME`. El loader acepta `config_path=Path("config/config.toml")`, lee `[models] directory` y aplica fallback legacy solo para defaults propios. `ModelStore(root=None)` delega a esa función.

El acceso default ocurre desde `main`, `api`, `application_wiring`, `downloads/planner`, `evaluate_compatibility` y `execute_model`. La creación física ocurre en `_open_root(create=True)` mediante `mkdir(parents=True)`, no al importar. `list_artifacts()` inspecciona sin crear.

## 4. Architecture Boundary

La responsabilidad mantiene esta dirección:

```text
CLI
→ configuration/bootstrap
→ existing Application use cases
→ existing Domain/Infrastructure
```

Packaging, versionado, rutas y CLI no deben entrar en Domain, Application, Compatibility Knowledge, Evaluation, Decision Policy ni Runner semantics. El acoplamiento actual es de bootstrap/adapters: `app.main` importa adaptadores y llama funciones existentes; `load_config()` y `default_models_directory()` dependen del cwd. Debe encapsularse sin redesign de negocio.

## 5. Package Design

- Nombre: `castlearq`.
- Requisito: `>=3.10`; no elevarlo.
- Backend: `setuptools.build_meta`; no cambiarlo en este bloque.
- El paquete instalable debe distribuir `app` y subpaquetes; el discovery exacto se validará en B9.30.
- No se requiere dependencia Python nueva identificada; no añadir por conveniencia.
- `pip install .` es mecanismo inicial de implementación/validación, no canal público definitivo.

## 6. Console Script Design

El metadata debe declarar:

```text
castlearq = app.main:main
```

`main()` sigue siendo el adaptador y dispatcher existente. El entry point solo debe invocarla y propagar su retorno; no duplicará parser ni lógica de `execute`, `run`, `chat`, `download` o `list`. `python3 -m app.main` y `castlearq` deben converger en `app.main.main()`.

## 7. Version Design

La fuente de verdad es `pyproject.toml` (`project.version = "0.1.0"`). Se debe exponer mediante metadata de distribución, preferentemente `importlib.metadata.version("castlearq")`, sin duplicar versión. `castlearq --version` debe producir salida corta y determinista, por ejemplo `castlearq <version>`, con exit 0.

El paquete instalado no puede depender de `pyproject.toml` en el checkout. Si metadata no está disponible durante ejecución fuente, se requiere fallback explícito y testeado, no un valor duplicado silencioso. La API que actualmente lee `pyproject.toml` debe revisarse para no depender del checkout instalado.

## 8. Configuration Resolution

Diseñar un resolver/bootstrap user-level con precedencia:

```text
CLI override → environment → user config → defaults
```

La ruta será `${XDG_CONFIG_HOME}/castlearq/config.toml`; sin esa variable, `${HOME}/.config/castlearq/config.toml`. Debe soportarse override explícito de ruta mediante la API/CLI que se decida, sin inventar variables. Si no existe el archivo, se usan defaults. Si existe pero es inválido, se emite error de configuración controlado y no se ocultan valores con defaults. El schema compatible con la configuración existente no se cambia.

`app/compatibility.py` puede conservar el parser de `CompatibilityConfig`, pero no debe recibir rutas relativas al cwd por defecto. El módulo exacto de bootstrap queda como decisión previa a implementación.

## 9. ModelStore Resolution

```text
new store exists → use new store
new absent + legacy exists → use legacy store
both exist → new wins
neither exists → use new path, creating only on write
```

La ruta oficial es `$XDG_DATA_HOME/castlearq/models`, con fallback `$HOME/.local/share/castlearq/models`; la legacy es `$HOME/.local/share/localai-hub/models`. Una configuración `[models] directory` explícita puede ser override de bootstrap, pero no elimina la prioridad de la ruta oficial sin configuración.

No crear el ModelStore durante imports, resolución, `--help`, `--version` o `list`. La creación física ocurre en la primera escritura mediante la existente operación `create=True`, preservando controles anti-symlink. Si no existe ninguno, `list` muestra vacío sin crear directorios.

## 10. Current Working Directory Independence

Las pruebas deben ejecutar el paquete instalado con cwd igual a `repository`, `/tmp`, `$HOME` y un directorio arbitrario. Help, version, configuración, ModelStore, imports y `list` deben ser equivalentes. No basta cambiar de directorio si el loader conserva una ruta relativa.

## 11. Installation Model

Validar inicialmente con:

```text
fresh environment → pip install . → castlearq --help → castlearq --version → castlearq list
```

`pip install .` es solo el mecanismo inicial de implementación/validación. El canal público queda abierto.

## 12. Clean Environment

La prueba mínima debe usar un entorno fresco, instalar el paquete, ejecutar sin `PYTHONPATH` y sin que el repositorio esté en el import path, e invocar:

```text
castlearq --help
castlearq --version
castlearq list
```

También debe confirmar que el proceso se ejecuta fuera del checkout y que no requiere imports desde la raíz del repositorio.

## 13. Runtime Independence

B9.30 no instala llama.cpp ni lo declara como dependencia Python automática. Con llama.cpp ausente, la instalación debe completarse y `--help`, `--version` y `list` deben funcionar. Cuando un comando necesite el runtime, debe producir un error de ejecución claro, mediante el flujo existente, sin convertir la ausencia en un error de importación o instalación.

## 14. Model Independence

La instalación no instala modelos. Con ModelStore vacío, deben funcionar `--help`, `--version` y `list`; `execute`/ejecución debe producir un error explícito de modelo ausente y orientar al flujo explícito de adquisición. La prueba no debe crear ModelStore durante comandos de solo lectura.

## 17. Migration Compatibility

Mantener temporalmente:

```text

```

Ambos deben delegar en `app.main.main()`. El bloque `__main__` conserva compatibilidad; el console script usa la misma función. El fallback legacy del ModelStore permanece sin migración automática. La documentación pública puede actualizarse durante implementación si es necesario, pero no se modifica README en este bloque.

## 18. Failure Semantics

```text
exit 0 → success
exit 1 → execution/preparation/runtime/model failure
exit 2 → CLI usage error
```

`argparse` ya produce 2 para uso inválido y `main()` devuelve códigos para handlers. Debe verificarse que `--version` devuelve 0, runtime/modelo ausentes devuelven 1 y `--help` conserva 0. Si algún camino actual mezcla 1/2, el cambio debe limitarse a la clasificación de B9.30 y documentarse; no se rediseña el dominio.

## 19. Security / Permissions Boundary

B9.30 no requiere `sudo`, `root`, `/usr` modification, system-wide config, driver installation ni system package installation. Instalación, configuración y datos son user-level. No se crean scripts de instalación ni se modifica el sistema.

## 23. Decisions Required Before Implementation

**Versión durante ejecución fuente sin metadata**

- Problema: `pyproject.toml` puede no existir fuera del checkout, mientras la API actual lo lee directamente.
- Evidencia: `app/api.py` resuelve el path relativo al paquete y devuelve `unknown` si no puede leerlo; no hay `importlib.metadata` en la CLI.
- Opciones: metadata de distribución con fallback explícito; helper de metadata; lectura de source solo en desarrollo.
- Impacto: evita duplicación y soporta paquete instalado.
- Recomendación neutral: usar metadata de distribución y hacer explícito el fallback de source.
- Decidir antes de escribir código: formato exacto del fallback y tests de API/CLI.

**Punto de integración de configuración y ModelStore**

- Problema: `load_config()` y `default_models_directory()` reciben paths relativos por defecto y los comandos construyen `ModelStore()` directamente.
- Evidencia: `app.main`, `api`, `application_wiring`, planner, evaluate y execute instancian el store.
- Opciones: resolver en bootstrap y propagar dependencias; método de contexto; cambiar defaults de funciones.
- Impacto: consistencia de cwd y de todos los comandos.
- Recomendación neutral: resolver en bootstrap/adapters e inyectar `Path` a consumidores, sin tocar Domain.
- Decidir antes de escribir código: módulo y API exactos de bootstrap.

No hay una decisión arquitectónica que exija rediseñar Domain/Application; sí deben cerrarse las dos decisiones de integración anteriores antes de implementar.
