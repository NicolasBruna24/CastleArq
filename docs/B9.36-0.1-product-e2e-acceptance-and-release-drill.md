## 7. ModelStore isolation

The drill environment used the official XDG resolution with a temporary data
home **and** a temporary `HOME`:

```text
XDG_DATA_HOME=/tmp/castlearq-b936-data
HOME=/tmp/castlearq-b936-home
resolved store = /tmp/castlearq-b936-data/castlearq/models
```

A first attempt that set only `XDG_DATA_HOME` was **rejected by the drill**:
`castlearq list` still reported a VERIFIED artifact, because the ratified
resolution contract falls back to the legacy store
`~/.local/share/localai-hub/models` when the new default does not exist and the
legacy one does. That is correct product behavior, not a defect, but it would
have silently reused a pre-existing artifact. Redirecting `HOME` as well makes
both the new default and the legacy candidate absent, so the official contract
itself resolves an empty store. No code or contract was changed; this is a
property of the drill environment.

Initial state, proven before acquisition:

```text
castlearq list → "No local model artifacts found."  (exit 0)
store files    → 0
```

## 18. Classification of observations

Nothing found in the drill was a CastleArq defect. Two observations deserve an
explicit category so they are not misread later:

1. **Legacy store fallback (environment interaction, not a defect).** Setting
   only `XDG_DATA_HOME` still resolved the legacy store, because the ratified
   contract prefers legacy when the new default is absent. Correct behavior;
   documented in §7 rather than "fixed".
2. **Ambiguous download selection (correct fail-closed behavior).** The product
   refused to guess an artifact and told the user exactly how to disambiguate.
