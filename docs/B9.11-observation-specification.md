# B9.11: OBSERVATION / CONTEXT ACQUISITION SPECIFICATION

## Independent Environment Observation Layer

### 1. Purpose

Block B9.11 establishes an independent, pure domain and probe subsystem for acquiring **verifiable facts from the local environment**.

Architectural hierarchy:
$$\text{OBSERVATION (B9.11)} \longrightarrow \text{KNOWLEDGE} \longrightarrow \text{EVALUATION} \longrightarrow \text{DECISION} \longrightarrow \text{EXECUTION}$$

B9.11 belongs **strictly** to Observation / Context Acquisition.
It represents **what an environment source observed**, not what the system concludes about compatibility or authorization.

### 3. Epistemic States: `ObservationState`

Ratified Decision **D-11.1**:
```python
class ObservationState(str, Enum):
    OBSERVED = "observed"
    UNAVAILABLE = "unavailable"
    ERROR = "error"
```

- **`OBSERVED`**: The fact was successfully acquired from the source.
- **`UNAVAILABLE`**: The required source or interface does not exist (e.g. `lspci` is not installed, `/etc/os-release` is missing).
- **`ERROR`**: The source was attempted, but failed (e.g. process timeout, crash, permission error).

#### Critical Distinctions:
$$\text{UNAVAILABLE} \neq \text{UNSUPPORTED}$$
$$\text{ERROR} \neq \text{UNSUPPORTED}$$
$$\text{UNKNOWN} \neq \text{FALSE}$$

#### Coverage is a separate dimension (not a fourth state)

`ObservationState` has **exactly** the three members above. "The family was never probed" is **not** an
`ObservationState`: it is recorded by the orthogonal `CoverageState` dimension
(`OBSERVED` / `NOT_OBSERVED`, see §4.F). In particular:

$$\text{NOT OBSERVED} \neq \text{OBSERVED + UNAVAILABLE} \neq \text{OBSERVED + ERROR}$$

#### `ObservedValue` invariants (enforced in `__post_init__`)

```text
OBSERVED     -> value is not None
UNAVAILABLE  -> value is None  AND detail is non-empty
ERROR        -> value is None  AND detail is non-empty
```

An omitted `value` and an explicit `value=None` are domain-equivalent. `detail=""` is invalid
(non-empty required). `source` must be non-empty.

### 4. Domain Contracts

Located in [`app/observation_domain.py`](file:///home/brunapc/LocalAI%20Hub/app/observation_domain.py). All objects are `@dataclass(frozen=True)` and all collections are `tuple`.

#### A. `ObservedValue`
Atomic fact container with state, raw value, provenance source identifier, and optional technical details.
```python
@dataclass(frozen=True)
class ObservedValue:
    state: ObservationState
    value: Any = None
    source: str = ""
    detail: str | None = None
```

#### B. `PlatformObservation`
Captures operating system family, kernel release, machine architecture, and Linux distribution ID.

#### C. `DeviceObservation` & `HardwareObservation`
Captures memory from `/proc/meminfo` and discrete display controllers from `lspci -nn` without synthetic vendor name mapping. System RAM is never copied into a fabricated `cpu` device; `devices == ()` when no structured device evidence exists. `HardwareObservation.acquisition_error: ObservedValue | None` is `None` on success and explicitly `UNAVAILABLE` (missing `lspci` binary) or `ERROR` (non-zero exit / timeout / `OSError`) otherwise. Each `DeviceObservation` and the `HardwareObservation` itself carry a `coverage: CoverageEntry` stating whether the device/driver/memory families were actually probed.

#### D. `RuntimeObservation`
Captures facts about installed runtime executables (strictly `llama.cpp` and `ollama`):
- `canonical_id`: "llama.cpp" or "ollama" (the fixed probing target declared by B9.11; not a Knowledge canonicalization mapping — identity canonicalization belongs to later architectural blocks)
- `executable_path`: Full path to binary
- `raw_version`: Exact version string from `--version` (`UNAVAILABLE` when the binary produces no output; `ERROR` on non-zero exit / timeout / `OSError`)
- `detected_backends`: Tuple of explicit backend strings per `detect_backend_evidence` (see §5.A); incidental prose and negations are NOT evidence.
- `backends_outcome`: `None` when the backend family was never probed (e.g. binary absent, or a runtime whose `--help` is not consulted); otherwise an `ObservedValue` whose state distinguishes "probed and no evidence" (`UNAVAILABLE`) from "probing failed" (`ERROR`).
- `coverage`: whether runtime discovery, version, and backend families were actually probed.

#### E. `EnvironmentContext`
Top-level snapshot binding the captured platform, hardware, runtimes, and snapshot timestamp.

#### F. `ObservationCoverage`
Orthogonal coverage dimension: `CoverageState.OBSERVED` / `CoverageState.NOT_OBSERVED`, one `CoverageEntry` per `ObservationFamily` (`PLATFORM`, `HARDWARE_MEMORY`, `HARDWARE_DEVICES`, `DEVICE_MEMORY`, `DEVICE_DRIVER`, `RUNTIME_DISCOVERY`, `RUNTIME_VERSION`, `RUNTIME_BACKENDS`). A family not listed is `NOT_OBSERVED`; duplicate families are rejected. Coverage precedes state: `NOT_OBSERVED` means the probe did not attempt the family, never "absence" or "unsupported".

### 5. Separation of Pure Parsers and Effectful Probes

Located in [`app/observation_probe.py`](file:///home/brunapc/LocalAI%20Hub/app/observation_probe.py).

#### A. Pure Parsers (Zero I/O)
- [`parse_os_release(text)`](file:///home/brunapc/LocalAI%20Hub/app/observation_probe.py#L197): Parses `/etc/os-release` lines into key-value pairs without file access.
- [`parse_meminfo(text)`](file:///home/brunapc/LocalAI%20Hub/app/observation_probe.py#L231): Returns `ParseMemResult` distinguishing `absent` (no `MemTotal` line), `bad_number` (numeric field absent/unparseable/negative) and `bad_unit` (unit missing or not an explicit `kb`/`b`/`mb` spelling). A bare number never implies bytes.
- [`parse_lspci_nn(text)`](file:///home/brunapc/LocalAI%20Hub/app/observation_probe.py#L282): Extracts device descriptions, 4-digit hex vendor IDs, and 4-digit hex device IDs verbatim.
- [`detect_backend_evidence(help_text)`](file:///home/brunapc/LocalAI%20Hub/app/observation_probe.py#L168): Pure backend-evidence predicate for `llama.cpp --help` (positive evidence only). A backend (`vulkan`/`cuda`/`sycl`) counts ONLY under one of three closed syntactic forms (case-insensitive):
  1. **Flag token**: `--<backend>` / `-<backend>` standing as a whole token.
  2. **Item list**: `backend`/`backends` followed by `:` or `=`, whose remainder is a list built **exclusively** from a closed vocabulary of backend-ish tokens (`cpu`, `gpu`, `vulkan`, `cuda`, `sycl`, `opencl`, `rocm`, `hip`, `metal`, `kompute`, `blas`, `none`, `all`, `auto`, `default`). Any other word makes the line prose — this rejects e.g. `backends: cpu only, cuda not compiled in` and `backend: CPU (CUDA disabled)`.
  3. **Build clause**: `built|build|compiled with <backend>` with the backend name **immediately** after `with` — this rejects e.g. `built with care; vulkan unsupported`.

  Negations, incidental mentions, and words placed elsewhere on a marked line are NOT evidence. No NLP, no proximity search, no scoring, no heuristic interpretation.

#### A2. Provenance Contract
Every `ObservedValue.source` describes the **actual operation that produced the fact**, never the conceptual technology. E.g. candidate resolution records the resolved candidate verbatim (`which:llama`, `which:llama.app`) or the real candidate list tried (`which:llama-cli,llama,llama.app`); a recorded absence never names a command that was not executed. Version/help probes record `command:<resolved-path> --version` / `command:<resolved-path> --help`.

#### B. Absence vs Error Contract
- `platform.system()` / `platform.release()` / `platform.machine()` returning empty/whitespace -> `UNAVAILABLE` with `value=None` (never the artificial string `"unknown"`).
- `/proc/meminfo` / `/etc/os-release` / `lspci` / runtime binaries missing -> `UNAVAILABLE` (`HardwareObservation.acquisition_error` records the missing `lspci` binary explicitly).
- `lspci` / `--version` / `--help` non-zero exit, timeout, or `OSError` while executing -> `ERROR` via `ObservedValue(detail=...)` or `HardwareObservation.acquisition_error` (never `pass`, never `UNSUPPORTED`).
- System RAM (`memory_total_bytes`) is never duplicated as a synthetic `cpu` `DeviceObservation`; `devices` holds only structured `lspci -nn` evidence.

#### B2. Acquisition errors vs programming defects
Only failures of the **external operation** (`TimeoutError`, `OSError` — the closed `ACQUISITION_ERRORS` category — plus non-zero exit codes and runner-signalled `error`) are converted into observational `ERROR` facts. Any other exception **propagates**: a programming defect is not an environment observation.

#### B3. Effectful Prober with Injected I/O (D-11.3)
`EnvironmentObserver` accepts injected callables:
- `command_runner: CommandRunner`: Runs commands with strict timeouts (no `shell=True`).
- `file_reader: FileReader`: Reads file contents safely.
- `which_finder: WhichFinder`: Resolves binary paths.
- `timestamp_provider: TimestampProvider`: Generates deterministic timestamps for testing (D-11.4).

### 6. No-Inference Guarantees

B9.11 enforces strict non-inference rules:
1. **No Vendor Fabrication**: PCI vendor `8086` is stored as `"8086"`, not transformed into `"Intel"`.
2. **No Backend Assumption**: The presence of a runtime binary does **not** imply CPU or Vulkan support. A backend is recorded ONLY on explicit syntactic evidence in `--help` (CLI flag `--<backend>`, `backend(s): ...` enumeration, or `built with <backend>`); incidental prose is NOT evidence.
3. **No Hardware Compatibility Linking**: The presence of an Intel or NVIDIA GPU does **not** imply that Vulkan or CUDA is functional.
4. **No Error-to-Unsupported Mapping**: If `lspci` is missing it is `UNAVAILABLE` (`acquisition_error`); if it exits non-zero, times out, or raises `OSError` it is `ERROR` (`acquisition_error`). Devices are never marked `UNSUPPORTED`, and failures are never hidden with `pass`.

---

### 7. What B9.11 Does NOT Do

B9.11 explicitly does **not**:
- Evaluate compatibility or generate `CompatibilityResult`.
- Produce `EvaluationDecision` (`ALLOW` / `DENY` / `ESCALATE`).
- Recommend or select backends or runtimes.
- Execute user prompts or inference models.
- Repair, install, or download software.
- Touch or replace legacy `app/hardware.py` or `app/runtimes.py`.
- Wire into production execution services.
