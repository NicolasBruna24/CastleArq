## 1. Purpose (§6.1)

B9.15 defines the **Evaluation Composition** stage of the CastleArq path: the
stage-scoped composition point immediately downstream of the Q-8 Evaluation
Entry Boundary. It is responsible for **assembly only**:

1. receiving the verbatim `IntegrationResult` delivered through Q-8;
2. receiving explicitly injected / caller-supplied dependencies;
3. RuntimeCapability reconciliation (**ownership here; algorithm DEFERRED**);
4. adapting `ModelSpec` / `ArtifactSpec` through the existing ratified
   `to_model` / `to_artifact`;
5. constructing `EvaluationContext` through the existing B9.8 contract;
6. invoking `evaluate(model, artifact, context)` and transporting the
   `CompatibilityResult` onward.

B9.15 is **composition, not domain interpretation**: it translates nothing,
decides nothing, selects nothing, executes nothing.

## 3. Composition Identity (§6.3)

Evaluation Composition is:

* a **dedicated, function-level composition point** (assembly of
  already-existing contracts: B9.8 adapter, B9.9 pipeline, B9.3 evaluator);
* strictly **downstream of Q-8**;
* **stage-scoped** — it composes the Evaluation stage only.

Evaluation Composition is **not**:

* another Application Composition Root (B9.14 owns exactly one — Q-9a);
* the Host / activator (Q-4: the Host activates; it does NOT compose);
* the Q-8 receiver (Q-8 accepts, retains and forwards only);
* Evaluation itself (see §11);
* Decision; Execution.

No concrete module / class / function name is fixed by this document.

## 4. Ownership (§6.4)

```text
Owner = future Evaluation-composition block (B9.13 §30)
```

Why ownership does NOT belong elsewhere:

* **B9.14 Application Wiring**: its contract ends at `IntegrationResult`
  (stop-line, I-Q9-08 / I-Q9-09); composing Evaluation there would move the
  stop-line.
* **Host**: Q-4 forbids composition and interpretation at the Host Boundary.
* **Q-8**: Q-8 must not construct `EvaluationContext`, reconcile
  `RuntimeCapability`, or evaluate — it would otherwise become a hidden
  Evaluation Composition Root.
* **Evaluation domain (B9.3)**: `evaluate()` receives already-assembled
  values; layer code never fetches, wires or locates anything.

## 5. Input Contract (§7)

| Value | Classification |
| --- | --- |
| `IntegrationResult` | **Primary input data** (via Q-8, verbatim) |
| `KnowledgeRegistry` | **Explicit injected composition dependency** |
| `RuntimeCapability` | **Caller-supplied evaluation-time value** |
| `ModelSpec` / `Model` | **Caller-supplied evaluation-time value** |
| `ArtifactSpec` / `ModelArtifact` | **Caller-supplied evaluation-time value** |
| `backend` | **Caller-supplied evaluation-time value** |
| `required_capabilities` | **Caller-supplied evaluation-time value** |
| `scope` | **Caller-supplied evaluation-time value** |

* **input data** = `IntegrationResult` (the observed-environment record);
* **composition dependencies** = the `KnowledgeRegistry`, received as an
  explicit parameter at the composition point (§7);
* **evaluation-time values** = capability, specs, backend, required
  capabilities, scope — declared by the caller per evaluation;
* **derived values** (never inputs): `EvaluationContext`,
  `KnowledgeProjection`, `StrictEvaluation`, `CompatibilityResult`.

No other input exists; none may be smuggled through another class.

## 6. IntegrationResult Contract (§8)

Evaluation Composition receives **the same `IntegrationResult`** delivered
through Q-8. **No replacement DTO, no envelope, no "EvaluationInput"
abstraction, no modification of `IntegrationResult`.**

Field roles:

* `entries[].knowledge` (`KnowledgeProjection`, incl. `runtime_knowledge`):
  observed-runtime **knowledge material** for reconciliation and episode
  traceability;
* `entries[].observation_identity`, `unmapped`, `trace` (`BoundaryTrace`):
  **provenance / episode information only** — they enter no
  `EvaluationContext` field, are invisible to `evaluate()`, and **must never
  be converted into Evaluation verdicts**.

Preserved identities (normative):

```text
UNMAPPED ≠ UNSUPPORTED        (B9.13 I-24 / §14: data entry, never a verdict)
ERROR ≠ UNAVAILABLE           (B9.11 epistemic states, verbatim)
ERROR ≠ UNSUPPORTED
```

## 7. Knowledge Registry Contract (§9)

```text
KnowledgeRegistry = explicit dependency (argument passing only)
```

The registry MUST NOT become: global; singleton; service locator;
dynamically selected; reconstructed per invocation; default-captured.
Evaluation code MUST NOT import `INITIAL_KNOWLEDGE_REGISTRY` merely because
it exists. The composition point **receives** the registry explicitly from
its activator (Q-3 discipline replicated for this stage). **No second
registry owner is created**: dataset ownership stays with
`app/initial_knowledge.py` (Knowledge layer); B9.14's Composition Root keeps
its Q-3 ownership of the `integrate()` leg.

## 8. RuntimeCapability Contract (§10) — mandatory distinction

```text
RuntimeCapability reconciliation OWNERSHIP:
    RATIFIED → Evaluation Composition

RuntimeCapability reconciliation ALGORITHM:
    DEFERRED
```

`RuntimeCapability` (`app/runtimes.py`, frozen dataclass: `name`,
`executable_path`, `version`, `supported_formats`, `supported_backends`,
`prompt_input_modes`, `supports_one_shot`, `available`, `reason`,
`compatibility_names`, `backend_arguments`) is the validated capability of a
detected runtime executable and the existing B9.9 input type. Its structural
relationship to `entries` runs through exact canonical-identity resolution
(`resolve_runtime`, B9.8 — no alias guessing).

This document does **NOT** invent: matching rules; multi-runtime policy;
priority rules; alias rules; backend preference; model-driven selection;
fallback behavior; absent-runtime policy. **Ownership is resolved while
algorithm design remains deferred** (B9.14 §15, B9.13 §30). When resolved,
the algorithm MUST land inside this block — not in Observation, Integration,
B9.14 wiring, or the Host.

## 9. Model / ModelArtifact Contract (§11)

Model information enters from **outside** the composition point
(caller-supplied). Evaluation Composition does NOT: discover models; select
models; load models; execute models. The existing adaptation remains the
authoritative mechanism:

```text
ModelSpec    → to_model(...)    → Model
ArtifactSpec → to_artifact(...) → ModelArtifact
```

No second adapter contract is created. `backend` is "chosen by a later layer
from model/artifact inputs (B9.8), never by the adapter" (B9.12 §18) and is
passed through `canonize_backend` (closed D-1 table). Model
discovery/loading source is deferred (§15).

## 10. EvaluationContext (§12)

The existing **B9.8 contract `build_evaluation_context(...)` remains
authoritative**; Evaluation Composition uses it rather than any parallel
context-construction mechanism. B9.8 is not modified.

| Field | Source | Rule |
| --- | --- | --- |
| `runtime: RuntimeKnowledge` | `projection.runtime_knowledge` ← `project_knowledge(resolve_runtime(registry, capability), scope)` | injected registry + caller capability |
| `backend: str \| None` | caller, `canonize_backend` (D-1) | never derived by observation/adapter |
| `hardware: HardwareSnapshot \| None` | **always `None`** | authoritative (B9.8 / B9.12 §18 / B9.3 never reads it) |
| `required_capabilities: tuple[str, ...]` | caller; B8.1 taxonomy validated | never derived from task / knowledge / capability |

Preserved (normative):

```text
EvaluationContext.hardware = None
raw EnvironmentContext does NOT enter Evaluation
```

`EvaluationContext` MUST NOT gain: an `IntegrationResult` field; an
`EnvironmentContext` field; a trace field; a capability field; a model field.

## 11. Evaluation Boundary (§13)

```text
Composition =
    assembly of inputs and dependencies: dependency injection,
    RuntimeCapability reconciliation (ownership), model/artifact
    adaptation, EvaluationContext construction
        ↓
Evaluation =
    interpretation performed by evaluate(model, artifact, context)
```

The boundary is exactly:

```text
EvaluationContext construction
        ↓
evaluate(model, artifact, context)      ← EVALUATION BEGINS HERE
```

`build_evaluation_context` executes no evaluation ("`evaluate()` is NOT
executed here" — B9.8); constructing the context is the final act of
composition. These responsibilities must not be blurred.

---

## 12. Error Semantics (§14) — preservation only

Evaluation Composition does NOT: reclassify; abort; retry; fallback;
recover; substitute; degrade.

```text
ERROR        → ERROR            (never UNAVAILABLE, never UNSUPPORTED)
UNAVAILABLE  → UNAVAILABLE
UNMAPPED     → UNMAPPED         (data entry; never UNSUPPORTED)
NOT_OBSERVED → coverage information (orthogonal dimension)
```

Observation states do not reach `evaluate()` (no field exists); they ride in
entries / unmapped / trace as episode data. Incomplete evidence continues
through the **existing** Evaluation contract: absent/unknown knowledge →
empty projection read as `UNKNOWN` → tri-state checks → Rule D →
`INSUFFICIENT_EVIDENCE` (B9.3 semantics). No new failure semantics are
created.

## 13. Lifecycle (§15)

```text
one activation
    → one Composition Root invocation
    → one Observation
    → one Integration
    → one IntegrationResult
    → one Q-8 delivery
    → one Evaluation Composition invocation
```

Preserved: no global state; no singleton; no cross-invocation cache; no
context reuse; no previous-result reuse. All involved contracts are frozen
dataclasses and pure functions (`evaluate_strict` "Pure"; `evaluate` "Pure
and deterministic"). If multiple evaluations are declared within one
invocation, this is a **caller-level declaration**, not an orchestration
policy introduced by this specification; each declared
`(model, artifact, capability)` tuple yields one `EvaluationContext` and one
`evaluate()` call.
