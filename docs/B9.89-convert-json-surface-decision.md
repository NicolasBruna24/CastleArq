## 2. Decision rationale

The implementation of `convert --json` already existed in `castlearq/main.py`
(`_JSON_COMMANDS` included `"convert"`, `convert_command(..., as_json=False)`
accepted `as_json=True` and produced the ratified envelope). The test
`test_wired_commands_are_exactly_the_ratified_set` was the only remaining
artifact that did not reflect the decision. This HADR ratifies the decision
and documents the resulting contract.

## 3. Envelope and exit codes

`convert --json` produces exactly one `castlearq.cli` envelope
(`schema_version = 1`) with:

- `command`: `"convert"`
- `exit_code`: the code the process will really return (0, 1 or 2)
- `payload`: command-specific data
- `warnings`: advisory strings (currently always empty)
- `error`: `{"kind", "message"}` or `null`

**Exit codes:**

- `0` — conversion completed successfully.
- `1` — the conversion service failed (e.g. `optimum-cli` not found,
  non-zero return code, timeout, or artifact registration failure).
- `2` — usage error (e.g. `source_path` does not exist, is not a directory,
  or contains a symlink).

### Success payload

```json
{
  "message": "Conversion completed",
  "success": true,
  "artifact": {
    "model_id": "...",
    "filename": "...",
    "quantization": {"value": "...", "status": "known"},
    "size_bytes": 12345,
    "sha256": "...",
    "content_id": "..."
  }
}
```

### Service failure payload

```json
{
  "message": "optimum-cli failed (exit ...): ...",
  "success": false
}
```

### Usage error envelope

```json
{
  "command": "convert",
  "exit_code": 2,
  "payload": {},
  "warnings": [],
  "error": {"kind": "usage_error", "message": "..."}
}
```

## 4. Distinction between usage error and service failure

- **Usage error** (`exit_code = 2`): the CLI never invokes the conversion
  service. The `error` field carries `{"kind": "usage_error", "message": ...}`
  and `payload` is `{}`.
- **Service failure** (`exit_code = 1`): the conversion service ran and
  returned a `ConversionResult` with `success = false`. The `error` field is
  `null`; the failure reason is in `payload.message` and `payload.success` is
  `false`.

This distinction is preserved by `convert_command` in `castlearq/main.py`
(lines 3370-3435) and by the tests in `tests/test_convert_cli.py` and
`tests/test_b9765_json_cli.py::ConvertJsonTests`.

## 5. Non-goals

- No new envelope shape is introduced.
- No new fields are added to the payload beyond the existing ones.
- No metadata speculative of the conversion (destination, task, revision,
  source path) is reported; those remain internal to the service.
