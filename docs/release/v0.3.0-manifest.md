# CastleArq `v0.3.0` — Release Manifest

> **Identity and evidence manifest.** This document records *what* `v0.3.0` is.
> It is not an installation guide, not a changelog and not a usage manual.

## 1. Release artifact identity

| Field | Value |
|---|---|
| Release version | `0.3.0` |
| Distribution | `castlearq` |
| Tag | `v0.3.0` (annotated) — not yet created at authoring time |
| Tag target | the commit that introduces this manifest; resolve with `git rev-parse v0.3.0^{commit}` |
| Python minimum | `>=3.11` |
| Build backend | `setuptools.build_meta` (`setuptools>=61`) |
| License | Apache-2.0 (included in both artifacts) |
| Build byte-reproducible | `false` — the artifacts below are the authoritative ones |

The **tag target is this manifest's own commit**, which does not exist when the
manifest is authored. The workflow resolves it from the tag itself; the
dispatch input is only a selector, never an authority.

## 3. Public surface delta since `v0.2.0`

`v0.3.0` is additive. No existing command, flag, argument or exit code was
removed or changed.

| Capability | Status |
|---|---|
| `castlearq import PATH` | new public command |
| `castlearq import PATH --label LABEL` | new public flag |
| `list` / `validate` / `compatibility` / `execute` of an imported artifact | new capability, addressed by label |

An imported artifact is addressed by the sanitized **label**, which is an
operational identifier and not a claim about the model's logical identity, which
may remain `UNKNOWN`. `models` continues to list the catalog only, and `list`
continues to list managed artifacts; the two remain separate by design.

## 4. Verification performed before publication

The artifacts were built locally and verified independently of the checkout:

- the wheel was installed into a temporary virtual environment outside the
  repository, and `app` resolved to that environment's `site-packages`, never to
  the source tree;
- `castlearq --version` reported `castlearq 0.3.0` and `--help` listed `import`;
- `import`, `list`, `validate` and `compatibility` were exercised against a
  synthetic GGUF fixture in a temporary model store under `/tmp`, leaving the
  developer's real model store untouched;
- the full test suite passed against the prepared source.

## 5. Publication chain

```text
annotated tag v0.3.0
  -> this manifest, committed in the tagged tree
  -> GitHub Release assets
  -> SHA-256 gate (fails closed on mismatch)
  -> PyPI via Trusted Publishing
```

The workflow never rebuilds the distribution. The exact artifacts whose digests
are recorded in §2 are transported, verified and published unmodified, so
rebuilding them after this point would invalidate this manifest.
