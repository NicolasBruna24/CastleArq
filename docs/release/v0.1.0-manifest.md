difference between them is exclusively documentary: the B9.37-A audit proved
the two commits produce byte-identical *extracted package content* (sdist trees
identical, wheel trees identical excluding `RECORD`, `pyproject.toml` and
`README.md` blob-identical, `docs/` never packaged).

## 5. Build reproducibility

```text
Build reproducibility: NOT byte-reproducible.

The recorded SHA-256 values identify the exact distribution
artifacts validated for this release candidate.

Rebuilding the same source commit may produce byte-different
archives while preserving equivalent extracted package content.
```

This is a **known and accepted property of the `0.1.0` build process**, not a
release failure. Concretely, two builds of the same commit produced different
archive hashes while their extracted contents were identical (timestamps inside
the zip/tar containers and `RECORD` regeneration are not normalized).

Operational consequences:

* publish the **exact** files whose hashes are recorded in §2;
* a third party verifying from source must compare **extracted content**, and
  must not expect the same hash from a fresh build;
* making builds byte-reproducible (pinned toolchain, `SOURCE_DATE_EPOCH`,
  normalized timestamps) is a post-`0.1.0` improvement, not a defect.
