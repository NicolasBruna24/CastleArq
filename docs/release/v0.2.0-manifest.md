## 4. Build reproducibility

```text
Build reproducibility: NOT byte-reproducible.

The recorded SHA-256 values identify the exact distribution
artifacts validated for this release candidate.

Rebuilding the same source tree may produce byte-different
archives while preserving equivalent extracted package content.
```

This is a known and accepted property of this build process, inherited from
`0.1.0` and not a release failure: timestamps inside the zip/tar containers
and `RECORD` regeneration are not normalized. Operational consequences:

* publish the **exact** files whose hashes are recorded in §2;
* a third party verifying from source must compare **extracted content**, and
  must not expect the same hash from a fresh build;
* making builds byte-reproducible (pinned toolchain, `SOURCE_DATE_EPOCH`,
  normalized timestamps) is a post-`0.2.0` improvement, not a defect.
