## 3. Runtime Artifact Support Current Contract

El nombre exacto es `runtime artifact support`. Se calcula en `app/compatibility_evaluator.py` mediante `_check_runtime(knowledge: RuntimeKnowledge)`.

La única entrada usada es `knowledge.supports_artifact`:

```text
True  -> PASSED
False -> FAILED
None  -> UNKNOWN
```

`RuntimeKnowledge` define esta propiedad como una afirmación runtime-level distinta del formato. El evaluator no combina ese booleano con `artifact.format`, `artifact.architecture`, `ModelSpec`, `GGUFArchitectureEvidence` ni backend. El check sólo registra `runtime.name` y `runtime.supports_artifact`.

## 4. Current Evaluation Flow

```text
execute_command
  -> evaluate_model_compatibility
       -> resolve ModelSpec + ArtifactSpec
       -> read physical GGUF architecture evidence
       -> compose_evaluation(..., physical_evidence)
       -> evaluate_strict
            -> project_knowledge
            -> RuntimeKnowledge
            -> _check_runtime
```

`compose_evaluation` y `evaluate_strict` ya transportan la evidencia física de architecture de forma separada. Esa evidencia afecta `_check_architecture`; no se convierte en `supports_artifact`.

## 6. First Evidence Loss / Missing Evidence Point

El punto faltante es Knowledge → RuntimeKnowledge:

```text
KnowledgeRegistry
  -> assertion runtime->artifact ausente
  -> project_knowledge()
       supports_artifact=None
  -> _check_runtime()
       UNKNOWN
```

No se pierde un path GGUF. La capability de llama.cpp demuestra availability, format y backends operacionales, pero no autoriza a convertir esos facts en la afirmación normativa `supports_artifact=True` que consume el check strict.

## 7. Runtime Evidence vs Artifact Evidence vs Backend Evidence

### Artifact evidence

```text
format = gguf
architecture = qwen2
size/checksum/state
```

Son observations del artifact. `format=PASSED` y `architecture=PASSED` demuestran que la knowledge reconoce esos facts.

### Runtime evidence

```text
llama.cpp executable available
version observed
one-shot capability observed
runtime can load GGUF
```

Son observaciones operacionales. No son necesariamente la misma cosa que `RuntimeKnowledge.supports_artifact`.

### Backend evidence

```text
CPU detected
Vulkan detected
```

El backend check compara el backend solicitado con `RuntimeKnowledge.supported_backends`. La disponibilidad de CPU/Vulkan no establece por sí sola `supports_artifact=True`.

## 8. Existing Representations Audit

| Representación | Apta para `supports_artifact` | Motivo |
|---|---:|---|
| `ArtifactSpec` | no | metadata operacional/declarada, no assertion runtime |
| `ModelSpec` | no | catálogo, no evidencia runtime sobre artifact |
| `ModelArtifact` | no | strict artifact facts, no assertion runtime |
| `ArtifactFilesystemInspection` | no | filesystem state, no Knowledge |
| `GGUFArchitectureEvidence` | no | evidencia física, no runtime support |
| `RuntimeCapability` | no directamente | detección operacional; no tiene tri-state ni provenance Knowledge |
| `RuntimeKnowledge` | sí | ya posee `supports_artifact: bool | None` y es el input exacto |
| `EvaluationContext` | no | contiene backend y runtime knowledge proyectada, no una assertion independiente |

No hace falta una nueva representación para el check actual: `RuntimeKnowledge.supports_artifact` ya es correcta. Falta la assertion Knowledge que la proyecte, si la evidencia normativa lo permite.


## 9. Persistence Analysis

`runtime artifact support` debe permanecer como afirmación de Knowledge, no como campo de artifact ni resultado cacheado del runner.

```text
physical artifact evidence = derived, read-only, ephemeral
runtime capability = detected, operational, fresh
runtime support knowledge = declarative KnowledgeRegistry assertion
evaluation result = derived
```

La evidencia de artifact no debe persistirse en manifest. La capability no debe persistirse como conocimiento normativo. El manifest conserva metadata declarada/adquisición y `ModelStore` deriva state local.

## 10. Error Semantics

| Situación | Semántica correcta | Estado actual |
|---|---|---|
| runtime no disponible | availability/policy failure | puede bloquear antes de B9.15 |
| runtime disponible, assertion ausente | `None` -> UNKNOWN | actual |
| assertion soportada | `True` -> PASSED | probada con fixture |
| assertion no soportada | `False` -> FAILED | probada con fixture |
| GGUF inválido | inspección física error | reader separado |
| backend no disponible | backend check separado | actual |

No se debe convertir `capability.available=True` ni `supported_formats=("GGUF",)` en `supports_artifact=True` sin una regla de Knowledge explícita.

## 11. Relationship With Backend

Son contratos distintos y parcialmente dependientes:

```text
runtime artifact support:
  RuntimeKnowledge.supports_artifact

runtime backend support:
  EvaluationContext.backend
  + RuntimeKnowledge.supported_backends/unsupported_backends
```

Un runtime puede declarar soporte GGUF pero no tener backend disponible. Un backend puede estar disponible sin que exista una assertion runtime→artifact. No son dos nombres para el mismo check.


El evaluator debe consumir evidencia declarada, no convertir una ejecución experimental en Knowledge permanente.

## 13. Architectural Options

### Opción A — Derive from runtime capability

```text
RuntimeCapability.available/supported_formats
  -> supports_artifact=True
```

Rechazada: mezcla observación operacional con Knowledge normativa y podría afirmar soporte para cualquier artifact basándose sólo en formato.

### Opción B — Derive from runtime + format

Requiere una regla que combine runtime knowledge y `artifact.format`. El check actual no implementa esa combinación y no debe adoptarse implícitamente.

### Opción C — Runtime + physical evidence

Potencialmente más precisa, pero mezcla Knowledge normativa con evidencia física efímera. Requiere una decisión adicional.

### Opción D — Explicit runtime-artifact evidence representation

Sólo sería necesaria si la assertion normativa depende de runtime + artifact físico y no puede representarse mediante `RuntimeKnowledge.supports_artifact`. No se crea en este bloque.
