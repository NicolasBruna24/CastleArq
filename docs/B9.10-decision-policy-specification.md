# B9.10: DECISION POLICY SPECIFICATION

## Pure Operational Policy Boundary

### 1. Purpose

Block B9.10 defines the boundary between **factual compatibility evaluation** and **operational authorization**.

- **Evaluation (B9.3–B9.9)** answers: *"What does the available evidence say about compatibility?"*
- **Policy (B9.10)** answers: *"What operational decision should be made from that evidence?"*

B9.10 does **not** evaluate compatibility, does **not** manufacture knowledge, does **not** perform system observations or hardware probing, and does **not** execute models. It purely consumes a [`StrictEvaluation`](file:///home/brunapc/LocalAI%20Hub/app/evaluation_pipeline.py) and applies a deterministic, frozen policy configuration to produce an [`EvaluationDecision`](file:///home/brunapc/LocalAI%20Hub/app/evaluation_policy.py).

---

### 2. Evaluation vs. Policy Distinction

The repository maintains an uncompromising separation of responsibilities:

| Layer | Responsibility | Input | Output | Allowed Operations |
| :--- | :--- | :--- | :--- | :--- |
| **B9.3 Evaluator** | Functional verification of claims | `Model`, `ModelArtifact`, `EvaluationContext` | `CompatibilityResult` | Tri-state evaluation (`PASSED`, `FAILED`, `UNKNOWN`) |
| **B9.9 Pipeline** | Pure composition of B9.8 + B9.7 + B9.3 | `KnowledgeRegistry`, `ModelSpec`, `ArtifactSpec`, `RuntimeCapability` | `StrictEvaluation` | Adapter translation, format canonicalization, context assembly |

| **Execution (Future)**| Process lifecycle & runtime dispatch | `EvaluationDecision`, `ExecutableArtifact` | `ExecutionResult` | Process execution, stdout/stderr streaming, process termination |

### 3. Domain Boundary & Data Types

The policy domain resides exclusively in [`app/evaluation_policy.py`](file:///home/brunapc/LocalAI%20Hub/app/evaluation_policy.py).

#### `DecisionVerdict`
```python
class DecisionVerdict(str, Enum):
    ALLOW = "allow"
    DENY = "deny"
    ESCALATE = "escalate"
```

- **`ALLOW`**: The system is authorized to proceed towards execution preflight.
- **`DENY`**: Operational execution is strictly forbidden (hard incompatibility or conflicting knowledge).
- **`ESCALATE`**: Terminal verdict indicating the evidence is insufficient to authorize execution automatically under current policy.

#### `PolicyReason`
```python
@dataclass(frozen=True)
class PolicyReason:
    code: str
    message: str
    check_name: str | None = None
```
- Immutable, factual explanation. Contains stable identifiers:
  - `COMPATIBLE_PASS`
  - `UNSUPPORTED_CHECK`
  - `INSUFFICIENT_EVIDENCE`
  - `BLOCKED_BY_CONFLICT`
  - `WAIVER_IDENTITY_UNKNOWN`

#### `EvaluationPolicyConfig`
```python
@dataclass(frozen=True)
class EvaluationPolicyConfig:
    policy_id: str = "strict-v1-zero-tolerance"
    allow_unknown_identity: bool = False
```
- Frozen, declarative configuration. Disallows silent implicit behavior.

#### `EvaluationDecision`
```python
@dataclass(frozen=True)
class EvaluationDecision:
    verdict: DecisionVerdict
    evaluation: StrictEvaluation
    reasons: tuple[PolicyReason, ...]
    policy_id: str
```
- **Preservation Invariant**: `evaluation` is preserved verbatim. No fields, projections, checks, conflicts, or provenance records are stripped, flattened, or altered.

### 4. Decision Function and Policy Semantics

#### `decide(evaluation: StrictEvaluation, policy: EvaluationPolicyConfig | None = None) -> EvaluationDecision`

Pure, deterministic mapping enforcing strict precedence:

```
        Evaluation & Projection
                   ↓
     [1. Conflicts in projection?] ─── Yes ───► DENY (BLOCKED_BY_CONFLICT)
                   ↓ No
        [2. Any check FAILED?]     ─── Yes ───► DENY (UNSUPPORTED_CHECK)
                   ↓ No
       [3. Any check UNKNOWN?]     ─── Yes ───► [Waiver allows identity alone?]
                   │                                     │                │
                   │                                    Yes               No
                   │                                     │                │
                   │                                     ▼                ▼
                   │                                   ALLOW           ESCALATE
                   │                        (WAIVER_IDENTITY_UNKNOWN) (INSUFFICIENT_EVIDENCE)
                   ↓ No
         4. All checks PASSED      ─── Yes ───► ALLOW (COMPATIBLE_PASS)
```

#### Precedence Order:
$$\text{CONFLICT} > \text{FAILED / INCOMPATIBLE} > \text{UNKNOWN / INSUFFICIENT\_EVIDENCE} > \text{COMPATIBLE}$$

1. **Conflicts (D-10.1)**:
   If `evaluation.projection.conflicts != ()`, the verdict is `DENY` with code `BLOCKED_BY_CONFLICT`.
   CastleArq never picks a winner, never ignores the conflict, and never downgrades it to `UNKNOWN`.
2. **Failed Checks**:
   If any check has `status == CheckStatus.FAILED`, the verdict is `DENY` with code `UNSUPPORTED_CHECK`.
3. **Unknown Checks & Insufficient Evidence**:
   - By default, any `UNKNOWN` check produces `ESCALATE` with code `INSUFFICIENT_EVIDENCE`.
   - `UNKNOWN` is **never** converted into `PASSED`.
4. **Explicit Identity Waiver (D-10.2)**:
   - The current model catalog does not carry cryptographic hashes, so `artifact-model identity` is routinely `UNKNOWN`.
   - If `policy.allow_unknown_identity == True` **and** the identity check is the **only** unknown check, the verdict maps to `ALLOW` with reason `WAIVER_IDENTITY_UNKNOWN`.
   - The check in `evaluation.result.checks` **remains `UNKNOWN`**. The waiver affects only the operational verdict, maintaining complete auditability.
   - The waiver **never** overrides `FAILED` checks, conflicts, or other `UNKNOWN` checks.
5. **Terminal ESCALATE (D-10.4)**:
   `ESCALATE` is terminal within B9.10. B9.10 does not prompt the user, does not execute fallbacks, and does not retry.

### 5. Purity and Determinism

- **Zero I/O**: No file reads, no network requests, no subprocess calls, no environment variable access.
- **Zero Legacy Contamination**: No imports of `app.compatibility`, `app.selection`, `app.execution_service`, `app.run_service`, or `app.runtimes`. No memory estimation, no VRAM estimation, no heuristic scoring, and no recommended runtime/backend aliases.
- **Immutability**: All structures are `@dataclass(frozen=True)`. All sequence attributes are `tuple`.
- **Determinism**: Given identical inputs, `decide()` produces strictly identical decisions.
